PREJETE RAČUNE (PR) IN KONTA
-----------------------------
- Privzeti stroškovni konto je 4190 (storitve).
- V zavihku »Prejeti računi (PR)« izberite eno ali več vrstic.
- Konto mora biti polna Minimax šifra (vsaj 4 mesta): 4170, ne 417. Ob povezavi
  z API se šifra preveri tudi proti šifrantu organizacije.
- Polje Konto je tudi filter šifranta: vpišite del šifre, na primer »417«, da
  se pokažejo kandidati (npr. 4170); shrani se lahko samo polna šifra.
  Iskanje ni občutljivo na velike črke ali šumnike (»stroski« najde »Stroški«).
  Filter deluje tudi v podrobnih obrazcih za popravek IR in PR. Prazen vnos
  oziroma puščica pri že izbranem polnem kontu ponovno pokaže ves šifrant.
- Po povezavi z API se konto in naziv prebereta iz šifranta izbrane Minimax
  organizacije, npr. »4000 — Stroški materiala«. V tabeli sta prikazana v
  ločenih stolpcih »Konto« in »Naziv konta«.
- Kliknite »Uporabi za izbrane«.
- Dvojni klik na posamezni PR, tipka Enter ali gumb »Odpri račun / popravi«
  odpre razširjeno podrobno formo. V istem oknu lahko spremenite konto, opis,
  datume, partnerja, davčno številko, vse zneske KPR ter potrditveni polji
  »Samoobdavčitev« in »DDV se odbija«. Podatki se prenesejo v delovno kopijo,
  Minimax XML oziroma API, izvorna datoteka pa ostane nespremenjena.
- Zneskovna polja v podrobni formi so prikazana in jih lahko vnašate v
  slovenskem zapisu, na primer 1.111,11. Program jih pri shranjevanju pretvori
  v notranji zapis, ki ga potrebujeta XML in API.
- Stalno vidni gumb »Shrani trenutni zapis« v podrobni formi spremembe samo
  začasno doda v delovno stanje programa; datoteke še ne zapiše. Tako lahko
  zaporedoma popravite več PR in IR.
- Ko so vsi začasni popravki pripravljeni, kliknite zgornji gumb »Shrani delovno
  kopijo«. Program pokaže skupni seznam popravkov in jih zapiše šele po potrditvi.
  Če potrditev zavrnete, popravki ostanejo v programu in jih lahko še dopolnite.
- Samoobdavčitev se ob prvem branju samodejno zazna iz polj KPR 9, 10 in 11,
  nato jo lahko za posamezni račun vključite ali izključite v podrobni formi.
- Za skupinsko nastavitev odbitka izberite enega ali več PR in kliknite
  »DDV se odbija« ali »DDV brez odbitka«.
- Če »DDV se odbija« ni označeno, se DDV vključi v strošek izbranega konta,
  v Minimax DDV-del se zapiše kot neodbitni DDV in se ne všteva v odbitni DDV
  polj 41, 42, 42a oziroma 43 kontrolnega DDV-O.
- Pri samoobdavčitvi program obračunani DDV knjiži v dobro konta 260xx. Če se
  DDV odbija, ga hkrati knjiži v breme konta 160xx; sicer se prišteje strošku.
- Če je vključeno »Zapomni si za dobavitelja«, bo program enak konto predlagal
  tudi pri njegovih prihodnjih računih.
- Kliknite »Shrani vse konte«, da se izjeme trajno zapišejo.
  Skupaj s konti se trajno shranita tudi obe nastavitvi DDV posameznih računov.

- Rumena KIR vrstica samoobdavčitve se ne izvozi kot izdani račun; program to
  jasno prikaže tudi v formi za popravek.

OBRAZEC DDV-O IN KONTROLNI PODATEK
---------------------------------
- Zavihek »DDV-O« se napolni samodejno takoj po odprtju KIR/KPR.
- Preklopna gumba »JSON« in »JSON + Minimax«: JSON pokaže vsa polja iz KIR/KPR;
  JSON+Minimax doda stolpec Minimax (samo listine, ki obstajajo v API) in razliko.
- Gumb »Minimax« (zeleni) je glavni tisk: uskladi z API, izvozi PDF/XML in pripravi
  znesek virmana (polje 51). Predogled / Izvozi PDF sta ločena gumba v isti vrstici.
- Program po FURS preslikavi sešteje polja evidenc KIR/KPR v polja DDV-O ter
  vrednosti obrazca zaokroži na cele evre.
- Na vrhu so prikazani obračunani DDV, odbitni DDV in rezultat: polje 51
  (obveznost) ali polje 52 (presežek).
- Zelena kontrolna vrstica preveri enačbo:
      obračunani DDV - odbitni DDV - polje 51 + polje 52 = 0 EUR
- Gumb »Kopiraj kontrolni podatek« kopira kratek povzetek v odložišče.
- Gumb »Shrani kontrolni pregled…« shrani vsa polja, vire seštevkov in
  kontrolno razliko v besedilno datoteko.
- Gumb »Izvozi PDF…« = tisk v PDF / izvoz v TROPS\{Zšt}\DDV\
  (npr. DDV O 2026 Q1.pdf + DDV_O_2026-Q1.xml). Obdobje z vrha (jan-mar …).
- PDF prikaz = uradni eDavki XSLT DDV_O_11.7-display-sl.xslt
  (isti kot hslsig:DisplayTransformDigest v eDavkih; lokalno v ddvo_transforms/).
- »Predogled« odpre isti PDF; »Shrani … drugam…« = druga pot.
- Kontakt: config ddvo_contact_name / ddvo_contact_phone.
- »Preračunaj« osveži obrazec iz trenutno odprtih evidenc.
- Vstopni DDV se v polja 41, 42, 42a oziroma 43 všteva samo pri računih, pri
  katerih je označeno »DDV se odbija«.
- V obrazcu PR: če je samoobdavčitev v KPR (P9–P11) ali shranjena za dobavitelja,
  program samodejno ponudi kljukici »Samoobdavčitev« in »DDV se odbija«.
  Ob »Zapomni si … za dobavitelja« se poleg konta shranita tudi ti dve nastavitvi.

NEPOSREDNA ODDAJA V MINIMAX API
-------------------------------
1. V levem drevesu izberite »Minimax -> API povezava in oddaja«.
2. Program sam uporabi obstoječo datoteko nastavitev Davčne blagajne:
       D:\PISARNA\Python\DavčnaBlagajna\blagajna_minimax_settings.json
   Gesla in client secret se ne kopirajo v nastavitve tega pretvornika.
3. Organizacije ni treba izbirati v API-zavihku. Ciljni Org_ID vedno določa
   podjetje, izbrano v levem seznamu. Kliknite »Poveži z izbranim podjetjem«.
   Ob povezavi program naloži tudi šifrant kontov (šifra + naziv) in ga shrani
   v predpomnilnik tega podjetja, da so nazivi vidni tudi brez nove povezave.
4. Za neposredni skupinski prenos uporabite enega od gumbov:
   - »Prenesi vse IR« za izdane račune,
   - »Prenesi vse PR« za prejete račune,
   - »Prenesi IR + PR« za obe knjigi skupaj.
   Program se po potrebi sam poveže, izbere še neoddane račune in opravi
   predpreverjanje. Pred dejansko oddajo vedno prikaže potrditveno okno.
   Nad gumbi najprej izberite način:
   - »Temeljnica + DDV« za popolno dvostavno knjižbo skupaj z DDV evidenco,
   - »Izdani/Prejeti račun — osnutek« za ustvarjanje dokumentov v modulu
     Izdani oziroma Prejeti računi.
   Nad tabelo lahko prikaz omejite z gumbi »Vsi«, »Samo IR« in »Samo PR«.
   Zadnji izbrani prikaz se shrani posebej za podjetje.
5. Posamezne račune lahko še vedno ročno označite v tabeli in kliknete
   »Predpreveri izbrane«. Program brez vpisa v Minimax preveri:
   Minimax preveri:
   - obstoj partnerjev po davčni številki,
   - vse uporabljene konte,
   - vrste temeljnic IR/PR,
   - DDV stopnje 22 %, 9,5 %, 5 %, oproščeno in neobdavčeno,
   - dvostavno ravnotežje vsake temeljnice.
6. Oddati je mogoče samo vrstice s stanjem »OK«. Kliknite »Oddaj izbrane v
   Minimax« in še enkrat potrdite organizacijo, število računov ter stanje.

V načinu »Temeljnica + DDV« program najprej ustvari knjižbene vrstice, nato
prek namenskega endpointa »journals/{id}/vat« doda DDV-vrstico in s ponovnim
branjem preveri, da je bila res zapisana. Zato se prenesejo tudi popravljeni
konti iz zavihkov IR/PR. Pri stanju »P - potrjeno« se temeljnica najprej ustvari
kot osnutek, dopolni z DDV in šele nato potrdi. Če DDV-korak ne uspe, program
jasno navede ID že ustvarjene temeljnice in je zaradi varnosti ne briše sam.

V načinu »Izdani/Prejeti račun — osnutek« program uporablja endpointa
»issuedinvoices« in »receivedinvoices«. V »Nastavitve DDV in računov« lahko za
vsako podjetje določite ID številčenja IR/PR, artikel za izdane račune, rok
plačila ter vrsto obračuna DDV. Prazno številčenje pomeni, da Minimax uporabi
svoje privzeto številčenje. Minimax na vsaki vrstici IR zahteva obstoječi
artikel. Program po povezavi naloži šifrant in sam predlaga artikel tipa
Storitev, prednostno s prihodkovnim kontom 7601; uporabnik ga lahko spremeni.
IR dobi artikel, vrstice z zneski in DDV stopnjami, nato ga v Minimaxu
pregledate in izdate. API za PR ob ustvarjanju sprejme glavo, partnerja, datume
in skupni znesek, ne pa odhodkovnih/DDV vrstic. Program v opombo PR-osnutka
zapiše predlagani konto odhodka, konto dobavitelja, osnovo, odbitni DDV in
samoobdavčitev.

V »Nastavitve DDV in računov« je zato na voljo možnost:
    PR: ustvari tudi ločeno temeljnico + DDV (oba ostaneta osnutka)
Ko je vključena, program najprej vedno ustvari PR-osnutek, nato še ločeno
osnutno temeljnico z izbranim stroškovnim kontom, obveznostjo do dobavitelja in
DDV-vrstico. V opisu obeh je referenca na PR in opozorilo »NE POTRDI OBEH«.
Minimax API teh dveh dokumentov ne poveže. V Minimaxu zato dokončajte in
potrdite samo PR ali samo spremljevalno temeljnico. Potrditev obeh bi podvojila
obveznost do dobavitelja. Možnost je zaradi varnosti privzeto izključena in se
shrani posebej za vsako podjetje.

Pri običajnem izdanem računu program ne pošilja vrste obračuna OD na sami
vrstici, ker jo Minimax določi iz artikla in DDV-stopnje. Izrecna vrsta se pošlje
samo pri posebni obravnavi (npr. OSS, prodaja na daljavo ali gradbeni posel).
Merska enota se prebere iz izbranega artikla, polje Value pa se ne pošilja, ker
je v API modelu samo za branje. Celotno API napako oziroma Location odprete z
gumbom »Prikaži cel rezultat«; odgovor lahko tudi kopirate v odložišče.

Pri uspešno oddanem PR-osnutku dvojni klik na vrstico ali gumb »Odpri PR-osnutek
+ vnesi odhodek« odpre uporabnikov prijavljeni Google Chrome. Program uporabi
točen ReceivedInvoiceId iz odgovora oziroma Location API, Org_ID izbranega
podjetja, konto odhodka iz KPR in osnove 22% / 9,5% / 5% (osnova = DDV ÷ stopnja).
Razširitev preklopi podjetje, odpre PR, klikne Uredi, največ enkrat Nov odhodek,
vnese konto, poskusi vnesti osnove in prikaže plavajoči »KIR/KPR paketek« z
gumbi Kopiraj (več slotov). Brskalnik ostane odprt. Pred odpiranjem program
vpraša: »Da« pomeni tudi samodejni klik Potrdi, »Ne« pripravi odhodek/osnove za
ročni pregled, »Prekliči« pa ne odpre računa. Če je na strani več gumbov Potrdi,
razširitev zaradi varnosti ne klikne nobenega.

Potrebna je razširitev »Minimax – odpiranje podjetij« v1.3.9 ali novejša iz mape:
    D:\PISARNA\Python\Chrome_add\AktivniZavihek_WebApp
    (ali D:\PISARNA\Python\Chrome_add\Minimax_Odpiranje_Podjetij — ista vsebina)
Po posodobitvi na chrome://extensions kliknite Reload. Razširitev ima dovoljenje
samo za moj.minimax.si, ne bere ali izvaža piškotkov in gesel.

Gumb »Zadnji potrjeni PR (API)« prebere zadnji potrjeni PR izbranega podjetja,
pokaže njegov dejanski ReceivedInvoiceId in ga kopira v odložišče. Naslednjega
osnutka program nikoli ne ugiba kot zadnji ID + 1; za novi osnutek uporabi ID iz
njegovega lastnega odgovora API.

STATUS RAČUNOV V PREGLEDU IR IN PR
----------------------------------
V zavihkih »Izdani računi (IR)« in »Prejeti računi (PR)« je stolpec »Status«.
Ko se povežete z Minimax API, program sam prebere račune iz obdobja odprtega
KIR/KPR in prikaže:
    - Osnutek  — Minimax status O,
    - Potrjen  — Minimax status P,
    - Ni najden — listina v izbranem podjetju/obdobju ni bila najdena,
    - Poveži API oziroma Ni preverjeno — status še ni bil prebran.

Za račune, ki jih je ustvaril ta program, se status prednostno preveri po
točnem IssuedInvoiceId oziroma ReceivedInvoiceId iz odgovora API. Pri starejših
računih brez shranjenega ID-ja se uporabi DocumentReference/listina. Gumb
»Osveži statuse IR/PR« na zavihku Minimax API stanje ponovno prebere, zato lahko
po potrditvi v Minimaxu takoj preverite prehod iz »Osnutek« v »Potrjen«.

Ostali gumbi za preverjanje ločene Playwright seje uporabljajo vgrajeni modul
``kirkpr_minimax_pw`` in skupni Chromium profil:
    %LOCALAPPDATA%\MinimaxBlagajna\PlaywrightProfile
Profil je skupen za vsa podjetja, do katerih ima isti Minimax uporabnik dostop.
Piškotki in prijavna seja ostanejo samo v Chromium profilu; program jih ne bere,
ne izvaža in ne zapisuje v svojo konfiguracijo.

PRIDOBIVANJE IZ ZIP (PRAVILA)
-----------------------------
Vhod je ZIP, JSON, XML ali CSV. Znotraj ZIP-a so dovoljeni člani:
JSON (FURS DDV_KIR_KPR), XML (FURS DDV_KIR_KPR) in CSV (P2… + KIR/KPR).

1. Program prebere vse .json / .xml / .csv člane v ZIP-u.
2. Če je nastavljen prednostni format (JSON/XML/CSV) in tak član obstaja,
   uporabi njega (oziroma združi člane tega formata).
3. Sicer izbere najpopolnejši vir: več vrstic, obe knjigi, nato JSON > XML > CSV.
4. Če primarnemu viru manjka KIR ali KPR, ga dopolni iz drugega člana ZIP-a
   (npr. ločeni KIR.csv + KPR.csv).
5. Če zunanji ZIP nima uporabnih podatkov, odpre ugnezdeni ZIP (1 nivo).
6. Če ni uporabnega KIR/KPR, javi napako s seznamom datotek v ZIP-u.

Prenos pridobljenih podatkov v Minimax: Minimax API ali datoteka XML za uvoz.

CSV
---
CSV lahko vsebuje KIR in KPR skupaj (stolpec KNJIGA z vrednostjo KIR/PR) ali v
ločenih datotekah znotraj ZIP-a. Program prepozna tudi imena KIR/IR in KPR/PR,
ločila ; , tabulator ali |, kodiranje UTF-8/Windows-1250 ter zneske 1.234,56.
Podprt je tudi FURS eDavki CSV brez imen stolpcev (prva vrstica = davčna +
OBDOBJE_OD/DO, nato vrstice KIR;… / KPR;…).
